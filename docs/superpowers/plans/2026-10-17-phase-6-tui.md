# Phase 6.4: TUI (Bubble Tea v2)

Status: **in Arbeit** (2026-10-17)
Stack #258, auf `feat/cli-command-user`.

## Ziel (Roadmap 6.4, Plan §7.3)

`streamcrew tui`: Bubble-Tea-v2-Oberfläche, die **nur über den
generierten API-Client** mit einem lokalen oder entfernten Core spricht.

## Aufteilung in PRs

### PR 1: Grundgerüst (M) — `feat/tui-framework`
- `internal/tui` + `streamcrew tui [--server URL] [--token] [--theme auto|light|dark]`
- Verbindung: `--server` (Default: `runtime.json` aus dem Datenverzeichnis
  lesen, sonst `http://127.0.0.1:8740`), Bearer-Token wie im CLI
- Layout: Header (Core-Status, Profil, Modus), Hauptbereich (aktive
  Ansicht), Footer (Tastenkürzel)
- Ansichten des Grundgerüsts: **Dashboard** (Status per Polling:
  Plattformen, Startzeit, Version, Queue-Pause)
- Tasten: `q` Beenden, `1..9`/`Tab` Ansichten, `?` Hilfe, `t` Theme
  (hellt/dunkel, ADR: helles und dunkles Theme)
- Fehlerzustand: Core nicht erreichbar ⇒ Banner + Retry mit Backoff
- Tests: teatest-Harness (Init/Update/Render, Theme-Wechsel, Fehler)

### PR 2: Ansichten (L) — `feat/tui-views`
- **Chat**: Stream-Subscribe (chat-Events), senden (ChatService.Send),
  Moderation per Tastenkürzel (Delete/Clear)
- **Event-Feed**: Stream-Subscribe (alle Event-Arten)
- **Command-Queue**: ListInstances, Pause (`p`), Abbrechen (`x`),
  Wiederholen (`r`)
- **Commands**: Liste + Suche, Ausführen (`Enter`), An/Aus (`e`),
  Bearbeiten in `$EDITOR` (Get ⇒ Datei ⇒ speichern ⇒ Update)
- **Nutzer**: List + Stat
- **Logs**: LogEntry-Events des Streams
- Login-Flow: AuthService-Status in Dashboard, StartLogin mit
  Device-Code-Anzeige (nur Anzeige; der Rest läuft im Core)
- Tests: teatest pro Ansicht mit simulierten Stream-Events

### PR 3: TUI-Tests (S) — in PR 1/2 mitgeliefert, eigener Abschnitt
- Golden-Tests des Renders (Theme-Wechsel, Ansichtswechsel)
- Test-Matrix in docs/tests/

## Entscheidungen

- Neue Abhängigkeiten: `charm.land/bubbletea/v2` v2.1.0,
  `charm.land/lipgloss/v2` v2.2.1, `charm.land/bubbles/v2` v2.2.1
  (latest, Code-ADR-0025-Regel)
- Die TUI kennt **keine** internen Pakete — nur `api/gen`-Client und
  `config` für das Datenverzeichnis (runtime.json).
- Stream-Verbindung: ein Subscribe pro laufender TUI-Session; Chat- und
  Event-Feed teilen sich den Stream (einziger Live-Kanal, ADR-0010).
- `--theme auto` folgt der Terminalhintergrund-Erkennung (lipgloss),
  `light`/`dark` erzwingen; `t` wechselt zur Laufzeit.
