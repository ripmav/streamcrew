# Test-Matrix: 7.3 TTS-Provider

Issue: Roadmap 7.3 — das Paket `internal/tts` (spec `overlays.md`
B41, B54, ADR-0020 §3): die Datei-Provider `google` (REST), `azure`
(REST, SSML) und `piper` (externer Prozess); der Provider `browser`
spricht auf der Overlay-Runtime und erzeugt keine Datei. Die Keys
kommen nur aus der Umgebung und nie in Logs; die erzeugten Dateien
landen unter `<media-dir>/generated/`.

| Test | Datei | Deckt ab |
|---|---|---|
| `TestGoogleCoversSynthesizeAndKeyHandling` | `internal/tts/tts_test.go` | B41/B54: POST mit Text und der Abbildung von Sprechrate (1.5) und Tonhöhe (1.5 → +10 Hz) im `audioConfig` — **ohne** `volumeGainDb` (Review 345-5: die Lautstärke greift nur im Sink, der Provider rendert mit Gain 1); der Key steht im Header `x-goog-api-key` und **nie** in der URL; die base64-Antwort wird als `tts-<zeitstempel>.mp3` unter dem Generated-Verzeichnis geschrieben; fehlender Key ist ein klarer Fehler, der die Env-Variable nennt. |
| `TestGoogleCoversTheAPIError` | `internal/tts/tts_test.go` | B54: ein API-Fehler trägt die Antwort im Fehler, der Key bleibt draußen. |
| `TestGoogleReusesTheKeepAliveConnection` | `internal/tts/tts_test.go` | Review 345-8: ein HTTP-Client in `New`, die Requests teilen Transport und Keep-Alive-Verbindungen — zwei Synthesen bedeuten genau ein Dial (zählender Dialer); das alte Code baute pro Request einen neuen `http.Transport` und dialte jedes Mal. |
| `TestAzureCoversSSMLAndKeyHandling` | `internal/tts/tts_test.go` | B41/B54: POST mit SSML (Sprache aus dem Vornamen der Stimme, `name` der Stimme, `prosody` rate/pitch in Prozent: 1.2 → `+20%`, 0.9 → `−10%` — **kein** `volume`-Attribut, Review 345-5: die Lautstärke greift nur im Sink), XML-Escapes im Text; ohne Voice in der Aktion ist die Default-Stimme `en-US-JennyNeural` (Review 345-6: das alte `en-US-Neural` existiert in der API nicht); Output-Format `audio-24khz-48kbitrate-mono-mp3`; der Key im Header `Ocp-Apim-Subscription-Key`, nie in der URL; fehlender Key und fehlende Region sind klare Fehler, die die Env-Variablen nennen. |
| `TestPiperCoversTheProcessAndModel` | `internal/tts/tts_test.go` | B41: der Prozess läuft mit `--model <tts-piper-model>`, `--output_file <erzeugte Datei>` und `--length-scale 1/rate` — **ohne** `--volume` (Review 345-5: die Lautstärke greift nur im Sink, und Piper machte aus 0 die volle Lautstärke); der Text geht auf stdin; die geschriebene Datei wird zurückgegeben; fehlendes Modell ist ein klarer Fehler, der `tts-piper-model` nennt. Der Pitch geht verloren (piper kennt kein Pitch-Flag — Shortcut, ADR-0020-Nachtrag). |
| `TestAzureSSMLEscapesTheLanguage` | `internal/tts/tts_test.go` | Review 345-7: das `xml:lang` ist der Voice-Name ohne das letzte Segment und wird wie der Rest des Dokuments escaped (`en-US-A&B-CNeural` → `xml:lang="en-US-A&amp;B"`); ein Voice-Name mit XML-Zeichen kann das SSML nicht brechen. |
| `TestGenerateCoversTheProviderNames` | `internal/tts/tts_test.go` | B41: `browser` erzeugt keine Datei (klarer Fehler, verweist auf das Overlay); unbekannter Provider ist ein klarer Fehler. |
| `TestNewCoversTheGeneratedDir` | `internal/tts/tts_test.go` | ADR-0020 §3: der Service braucht das Generated-Verzeichnis unter dem Medienverzeichnis des Profils. |

Nicht abgedeckt: die echten Cloud-APIs (nur httptest-Fakes — die
Abbildung der Parameter ist geprüft, nicht die Provider-Antworten) und
der echte piper-Prozess (Fake-`PiperRun`; die Prozess-Klammer läuft im
App-Wiring `piperRun`).
