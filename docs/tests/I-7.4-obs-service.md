# Test-Matrix: 7.4 OBS-Service

Issue: Roadmap 7.4 — die OBS-Verbindung (`internal/obs`,
spec `overlays.md` B42, B43, B44, B55): obs-websocket v5 über den
eigenen Client in `internal/obs/client.go` (coder/websocket,
Code-ADR-0015; `goobs` fällt an der Lizenz-Allowlist für
`hashicorp/logutils` (MPL-2.0) weg); ohne OBS beim Start gibt der Core
ohne Retry auf, eine abgerissene Verbindung reconnectet alle 5 s; die
Ereignisse der Verbindung laufen auf dem Bus, jede Änderung einmal;
die Operationen der `streaming_software`-Aktion laufen auf der aktiven
Verbindung.

Test-Infrastruktur: ein Fake-OBS-Server (coder/websocket,
`http.Server` + `Accept`) mit der obs-websocket-v5-Verhandlung
(Hello vom Server → Identify mit der Passwort-Authentifizierung,
Close-Code 4009 bei abgewiesener Auth, `Identified`), den Requests
(op6 → op7 mit Status 100) und den Events (op5) auf einem
`127.0.0.1`-Listener.

Nicht abgedeckt: eine echte OBS-Instanz (Fake — die Wire-Details
folgen der obs-websocket-v5-Spezifikation) und der Netguard-Pfad (in
der `app`-Verdrahtung, Code-ADR-0019).
