# Test-Matrix: I-6.5.2 ConfigService-API

Roadmap 6.5 (On-the-fly-Konfiguration), 6.5.2: die `ConfigService` der API.
`Get` liefert das aktuelle Dokument mit den Kategorien der Einstellungen,
`Update` validiert und speichert ein Dokument (der Watcher wendet die
Hot-Änderungen an). Beide RPCs brauchen Admin; live nur im Server-Modus.

## Erwartetes Verhalten

| Fall | Erwartet |
|---|---|
| `Get` im Server-Modus | Dokument (aktuelle effektive Werte), `hot`, `fixed` (per Flag/Env fixiert), `restart`-Listen, `live: true` |
| `Get` im Daemon-/Desktop-Modus | Dokument, `live: false` (Read-only) |
| `Update` mit gültigem Dokument | Dokument wird atomar (tmp + rename, 0600) gespeichert; `applied` = geänderte hot-Einstellungen, `restart` = geänderte Nicht-Hot; der Watcher wendet an |
| `Update` mit gleichem Inhalt | kein Write, `applied` leer |
| `Update` mit unbekanntem Key | InvalidArgument, Datei bleibt unverändert |
| `Update` mit ungültigem Wert | InvalidArgument, Datei bleibt unverändert |
| `Update` ohne Datei/Watcher oder ohne Server-Modus | FailedPrecondition |
| `Update` erzeugt eine fehlende Datei | Datei wird angelegt |
| Scope | `Get` und `Update` brauchen Admin (fail-closed) |
| `config show` / `config show --json` | vollständiges Dokument inkl. `tls_cert`, `tls_key`, `cors_allow` (omitempty) |
