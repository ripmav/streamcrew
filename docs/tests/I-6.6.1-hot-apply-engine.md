# Test-Matrix: I-6.6.1 Hot-Apply-Engine

Roadmap 6.6 (On-the-fly-Konfiguration), 6.6.1: Hot-Apply-Engine im Core +
Code-ADR-0021. Erwartetes Verhalten je Setting:

| Setting | Hot | Erwartet bei Datei-Änderung (Server-/Daemon-Modus, Wert nicht per Flag/Env fixiert) |
|---|---|---|
| `log-level`, `log-component-level` | ja | Sofort in allen Komponenten gültig, Logger wird nicht neu aufgebaut |
| `log-format` | ja | Konsole wechselt text ↔ json, für alle abgeleiteten Logger |
| `log-file`, `log-max-size`, `log-max-files` | ja | Neue Rotationsdatei wird geschrieben, alte geschlossen |
| `dry-run` | ja | an: Chat/Moderation/Twitch-Ops werden aufgezeichnet; aus: sie laufen |
| `dev` | ja | pprof-Routen 200 ↔ 404 |
| `cors-allow` | ja | Allowlist wird getauscht, Cross-Origin entsprechend 200/403 |
| `listen`, `tls-cert`, `tls-key` | ja | Rebind: neuer Bind dient, alter endet; Fehler ⇒ alter Bind bleibt |
| `mode` | ja | Host-Rechte neu berechnet (Basis des Modus + Grant/Revoke) |
| `shutdown-timeout` | ja | Neuer Wert wird beim Shutdown gelesen |
| `grant`, `revoke`, `file-root`, `outbound-allow` | ja | Unverändert wie Code-ADR-0019 |
| `data-dir`, `profile`, `config` | nein | „configuration changes apply after a restart“ |
| jedes Setting per Flag/Env fixiert | — | Datei-Änderung wird nicht angewendet |
