# Test-Matrix: 7.3 TTS-Action

Issue: Roadmap 7.3 — die Aktion `text_to_speech`
(`internal/action/tts`, spec `overlays.md` B41, B43, B49, B54,
ADR-0020 §2/§3): ein Template-Text über den Provider `browser`
(Default, Web Speech API der Overlay-Runtime), `google`, `azure`
oder `piper`; Stimme, Lautstärke, Rate, Pitch, `waitForFinish`, Sink.

| Test | Datei | Deckt ab |
|---|---|---|
| `TestConformance` | `internal/action/tts/tts_test.go` | Code-ADR-0013, Punkt 9: das Schema (draft 2020-12, `x-ui`-Vokabular) akzeptiert ein Beispiel genau dann, wenn Dekodierung + Validierung es tun; stabile Encodierung; Schema-Mitglieder = Dokument-Mitglieder; Golden `testdata/text_to_speech/v1.golden`. Beispiele: Text (Default-Volumen 100, Rate/Pitch 1), alle Optionen (piper, voice, volume 80, rate 1.5, pitch 0.8, wait, sink local), Template im Text; fehlender/leerer Text, unbekannter Provider, Volume 101, Rate −0.5, Pitch −1, unbekannter Sink. |
| `TestValidate` | `internal/action/tts/tts_test.go` | B41: leerer Text, unbekannter Provider, Volume < 0 bzw. > 100, negative Rate/Pitch, unbekannter Sink sind klare Fehler; Rate/Pitch 0 ist gültig (bedeutet „Default 1“). |
| `TestTTSSpeakBrowser` | `internal/action/tts/tts_test.go` | B41: der Default-Provider `browser` spricht den gerenderten Text über den Browser-Port; Rate 0 und Pitch 0 werden zur normalen 1 gerendert; es wird **keine** Datei gespielt (keiner der Sinks wird aufgerufen). |
